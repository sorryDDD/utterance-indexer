## 전제 — 어디서 출발하는가

작업계획서가 승인되었다. 이 타스크는 **코드를 고치지 않은 기준선**과 **원리적 버그를 고친 뒤의 결과**를 같은 라벨·같은 채점 기준으로 비교한다.

단계는 둘이다. 단계 1은 채점 하니스를 만들고 현행 기준선을 확정한다. 그 결과가 화자 판별 수정 범위를 바꿀 수 있으므로 단계 승인을 받은 뒤에만 단계 2로 넘어간다. 단계 2는 승인된 원리적 버그만 고치고 같은 조건으로 재측정한다. 임계·감도 튜닝, 추가 라벨링, 아키텍처 변경은 하지 않는다.

## 채점 기준 — 두 단계에서 바꾸지 않는다

수정 전후 비교가 성립하려면 채점 규칙을 코드 수정 전에 동결해야 한다. 단계 1에서 아래 규칙을 합성 자료로 검증한 뒤 기준선에 적용하고, 단계 2에서는 그대로 재사용한다.

### 입력과 범위

채점 하니스 `tests/evaluate_session.py`는 `schema_version` 2의 라벨 JSON 하나와 이름을 붙인 `segments.json` 하나 이상을 입력받는다. 실제 라벨·산출물은 저장소 밖에 두며, 반복 옵션 `--segments 이름=경로`로 합집합 기준선·Silero 단독·수정 후 결과를 같은 실행에서 비교할 수 있게 한다.

- 라벨의 `covered`를 겹치지 않는 오름차순 구간으로 정규화한다.
- `covered` 밖의 라벨과 검출 구간은 채점에서 제외한다. 경계를 걸친 검출 구간은 `covered` 안쪽 부분만 센다.
- 라벨은 `target`·`clinician`·`unsure`·`other_voice`만 허용하고, 시각·정렬·범위·스키마가 잘못되면 수치를 내지 않고 종료 코드 1로 끝낸다.
- 여러 검출 구간이 서로 겹치면 시간 집계에서는 합집합을 써 중복 시간을 세지 않는다. 개수 집계는 원래 검출 구간 단위로 유지한다.
- 입력 경로·영상 이름·라벨 원문은 표준 출력의 결과 표에 싣지 않는다. 출력은 이름과 집계 수치만 담는다.

### 구간 대응

정답 구간 `[a, b]`와 검출 구간의 겹침이 **정답 길이 `(b-a)`의 15%를 초과**하면 그 검출 구간을 정답의 적중으로 본다. `tests/regression.py`의 현재 기준과 `>` 비교를 그대로 쓴다. 정확히 15%인 경계 사례는 적중이 아니다.

하나의 정답에 여러 적중 구간이 있을 수 있다. 검출 재현율은 적중 구간이 하나라도 있으면 성공으로 세고, 화자 판별은 그중 하나라도 `is_target=true`이면 대상자 후보로 성공한 것으로 센다. 동시에 **검출된 정답만을 분모로 둔 조건부 화자 배정 성공률**도 함께 내어 VAD 실패와 화자 판별 실패를 분리한다.

### 지표

각 `segments.json`에 대해 다음을 낸다.

1. **대상자 검출 재현율** — 확정된 `target` 전체에서 적중한 비율.
2. **참여자 검출 재현율 보조값** — `target+unsure`를 분모로 한 값. `unsure`를 제외한 중심값과 함께 보고한다.
3. **짧은 대상자 부분집합** — 길이 0.5초 미만 `target`의 검출 재현율과 대상자 후보 성공률.
4. **오탐 총량** — `covered` 안에서 `target`·`clinician`·`unsure`·표시된 `other_voice` 어느 것과도 겹치지 않는 검출 구간의 개수와 총 시간. 표시되지 않은 제3자 발성이 섞일 수 있으므로 비발성 오탐이나 잡음 오탐이라고 부르지 않는다.
5. **화자 판별 성적** — 임상가 라벨과 조금이라도 겹친 `target`을 제외한 대상자 라벨에서 대상자 후보로 성공한 비율. 검출 실패를 포함한 값과 검출 성공분만의 조건부 값을 함께 낸다. 제3자 미표시 때문에 깨끗한 조건의 성적이라고 해석하지 않는다.
6. **임상가 발성의 대상자 후보 혼입률 보조값** — 대상자·`unsure`와 겹치지 않는 임상가 라벨 중 `is_target=true` 검출 구간과 적중한 비율. 대상자 후보 목록에 임상가 발성이 얼마나 섞였는지 보는 보조값이며 중심 지표로 승격하지 않는다.
7. **표지 안전성** — `src == "E"` 또는 `f0 == 0`인 검출 구간을 각각 제거했다고 가정했을 때 대상자 검출 재현율이 얼마나 떨어지는지 계산한다. 하락이 0이 아니면 그 표지를 배제 게이트로 쓰지 않는다.
8. **표지 유용성** — 각 표지가 붙은 검출 구간의 개수·시간과 그중 참여자 라벨에 적중하지 않은 구간의 비율을 낸다. 안전성과 유용성을 함께 보아야 게이트 후보인지 판단할 수 있다.
9. **무리 진단** — 화자 무리별 구간 수·총 시간과, 각 무리를 대상자로 간주했을 때의 대상자 후보 성공률을 낸다. 가장 좋은 무리를 사후 선택한 값은 **알고리즘 성적이 아니라 무리 자체에 대상자 신호가 남았는지 보는 진단 상한**으로만 쓴다.

`--vad silero` 단독과 합집합은 같은 라벨에 짝지어 위 지표를 각각 내고, 대상자별로 **둘 다 적중 / 합집합만 적중 / Silero만 적중 / 둘 다 놓침**의 네 칸도 집계한다. 이 비교로 합집합이 추가한 재현율과 오탐 부담을 동시에 본다.

### 출력과 보관

하니스는 사람이 읽는 표를 표준 출력에 내고, `--json-output`을 지정하면 같은 집계를 JSON으로 쓴다. 실제 회기에서 나온 JSON은 파이프라인 산출물과 같은 외부 보관 폴더에만 두고 저장소에 넣지 않는다. 단계별 완료보고서와 논의 스레드에는 집계 수치와 해석상의 제약만 옮긴다.

## 단계 1 — 채점 하니스와 현행 기준선

### 1단계 무엇

#### 1. 기준선 보존과 입력 대응 확인

첫 동작으로 현재 남아 있는 현행 산출물을 **새 고유 폴더에 복사**한다. 기존 폴더와 파일은 삭제·이동·덮어쓰기하지 않는다. 라벨의 영상 식별자와 길이, `covered`, 산출물의 시각 범위를 로컬에서 대조해 같은 회기인지 확인하되 실제 파일명과 경로는 보고서에 적지 않는다.

입력 위치가 자동으로 하나로 확정되지 않으면 추측해 진행하지 않고 작업지시자에게 경로 확인만 요청한다. 확인 과정과 이후 처리는 전부 로컬이며, 어떤 파일도 외부 서비스에 보내지 않는다.

보존 사본과 별도로 현재 `speech_index.py`를 `--no-asr`로 실행해 **합집합 기준선**과 **Silero 단독 기준선**을 서로 다른 새 폴더에 만든다. 두 실행은 같은 영상과 기본 파라미터를 쓰며, 소스 리비전과 명령 옵션을 외부 기준선 메타데이터에 남긴다. 전사를 생략해 전사 내용이 새로 생기지 않게 하고, 이미 있는 기준선과 재실행 결과가 다르면 측정 전에 원인을 규명한다.

#### 2. 채점 하니스 구현

`tests/evaluate_session.py`를 표준 라이브러리만으로 구현한다. 실전 파일 없이 검증할 수 있도록 `--self-test`를 두고, 임시 디렉터리에 합성 라벨·합성 검출 JSON을 만들어 다음을 확인한다.

1. `covered` 밖 제외와 경계 걸침 자르기
2. 15% 초과 적중과 정확히 15%인 비적중
3. 대상자·`unsure` 포함/제외 재현율
4. 0.5초 미만 부분집합
5. 임상가 중첩 대상자의 화자 판별 제외
6. 검출 실패와 조건부 화자 배정 실패의 분리
7. 오탐 구간 개수와 중복 없는 총 시간
8. `E` 단독·`f0=0` 제거의 반사실 재현율
9. 합집합·Silero 단독의 네 칸 짝지은 비교
10. 잘못된 스키마·범주·시각 입력의 실패

#### 3. 기준선 측정과 초안 분석

검증된 하니스로 보존된 현행 산출물, 재실행한 합집합, Silero 단독을 채점한다. 보존 산출물과 재실행 합집합의 핵심 지표가 일치해야 기준선을 확정한다. 일치하지 않으면 소스·옵션·입력 대응을 확인하고, 어느 쪽을 기준선으로 삼을지 임의로 고르지 않는다.

## 단계 2 — 원리적 버그 수정과 재측정

### 2단계 무엇

#### 1. F0 탐색과 옥타브 하강 교정

현행 자기상관 방식은 유지하되 다음만 고친다.

- 탐색 범위를 60–400 Hz에서 **60–600 Hz**로 넓힌다. 600 Hz는 Praat의 raw autocorrelation 표준 상한이며, 현재와 같은 원시 자기상관 방식에서 임의의 실전 라벨 튜닝 없이 채택할 수 있는 고정 기준이다. 근거는 [Praat raw autocorrelation 설명](https://praat.org/manual/pitch_analysis_by_raw_autocorrelation.html)이다.
- 범위 안 자기상관의 단일 최댓값만 고르지 않고 지역 최댓값들을 후보로 모집한다. 후보 강도에 **옥타브당 0.01의 고주파 선호 비용**을 적용해, 같은 주기성이 배수 지연에서 반복될 때 낮은 옥타브로 접히는 것을 줄인다. 이 값도 Praat raw autocorrelation의 표준값을 그대로 쓰며 실전 라벨로 조정하지 않는다.
- `f0 == 0`만으로 모든 실패를 뭉뚱그리지 않는다. 구간별 `segments.json`에 `f0_status`(`ok`·`unvoiced`·`octave_corrected`)와 `f0_corrected_fraction`을 추가한다. 새 후보가 400 Hz를 넘고 기존 60–400 Hz 최댓값이 그 절반 부근이었던 프레임을 옥타브 교정으로 기록하며, 구간 값은 채택된 프레임들의 중앙값으로 유지한다.
- 임베딩에는 교정된 F0를 넣는다. F0를 발성 배제 게이트로 새로 쓰지는 않는다.

합성 검증에는 250 Hz와 500 Hz 주기 신호, 무음, 0.12초 짧은 신호를 넣는다. 250 Hz는 기존 범위와 같은 값으로 유지되고, 500 Hz는 250 Hz로 접히지 않으며 `octave_corrected`로 추적되고, 무음은 `unvoiced`와 0.0을 내야 한다. 단순 자기상관이 모든 실제 음성의 옥타브 오류를 해결한다고 주장하지 않고, 결과보고서에 남은 한계로 적는다.

#### 2. 대상자 무리 선택 기준

〈단계 1 승인〉에서 포함하기로 판정한 경우에만 기본 무리 선택을 **구간 수가 가장 적은 무리**에서 **검출 구간 총 시간이 가장 짧은 무리**로 바꾼다. 라벨은 선택 알고리즘에 넣지 않고, 각 무리의 `sum(end-start)`만 쓴다. 참조 발화를 지정한 경로는 그대로 둔다.

선택 로직을 작은 함수로 분리하고, 「구간 수는 많지만 총 시간이 짧은 무리」가 대상자로 선택되는 합성 사례를 `tests/regression.py`에 추가한다. 단계 1에서 무리 자체에 대상자 신호가 없다고 판정되면 이 변경과 테스트는 만들지 않고, 제외 이유를 단계 2 보고서에 남긴다.

#### 3. 같은 조건 재실행과 비교

수정 후 파이프라인을 같은 영상·같은 기본 파라미터·`--no-asr`로 새 고유 폴더에 다시 실행한다. 기준선 폴더를 덮어쓰지 않는다. 합집합과 Silero 단독을 모두 다시 만들고 단계 1의 동결된 하니스로 채점한다.

수정 전후 비교는 절대값과 변화량을 함께 낸다. 중심 비교는 대상자 검출 재현율, 화자 판별 성적, 짧은 발성 부분집합, 오탐 총량이며, F0 상태 분포와 무리별 구간 수·총 시간은 원인 진단으로 붙인다. F0와 무리 선택은 VAD 구간 자체를 바꾸지 않으므로 검출 재현율·오탐 총량이 달라지면 의도하지 않은 변화로 보고 조사한다.

새 실측은 기존 스레드 글을 고쳐 쓰지 않고 다음 글에 남긴다.

- 신규: `docs/topics/003_화자_판별_방식/07_F0와_무리_선택_수정_전후_비교.md`
- 수정: `docs/topics/003_화자_판별_방식/000_색인.md` — `06` 기준선과 `07` 수정 후 결과를 연결하고, 채택할 수 있는 결론과 표본 한계 때문에 보류할 결론을 분리한다.

### 2단계 작업지시자 판정

단계별 완료보고서에 수정 전후 표, 자동 검증, 표본 한계와 AI의 초안 분석을 제시한다. 작업지시자는 다음을 판정한다.

1. 원리적 버그가 계획대로 고쳐졌는가.
2. 수정 후 대상자 후보 성적이 실제로 나아졌는가, 같아졌는가, 나빠졌는가.
3. 회기 하나의 편향된 표본과 제3자 미표시를 감안할 때 이 결과로 무엇까지 말할 수 있는가.
4. 다음 방향을 튜닝·추가 라벨링·녹음 조건·아키텍처 논의 가운데 어디에 둘 것인가.

AI는 2~4의 초안 분석까지만 하고 판정을 대신하지 않는다. 〈단계 2 승인〉은 단계 2 변경의 커밋까지만 허용하며, 최종 결과보고서 작성·마감·원격 반영 승인은 포함하지 않는다.

## 최종 결과보고서 직전의 정지점

단계 2가 승인·커밋되면 이 실행계획의 구현과 단계별 검증은 끝난다. 여기서 멈추고, 별도 지시를 받은 뒤 최종 결과보고서 `docs/report/task_m010_2_report.md`와 완료일 orders를 작성한다. 결과보고서에는 계획 대비 결과, 동결한 채점 정의, 기준선과 수정 후 비교, 표본 한계, 작업지시자 판정, 남은 일을 담고 논의 스레드의 결론을 인용한다.

## 승인 관문

현재 남은 관문은 **실행계획 승인 → 단계 1 승인 → 단계 2 승인 → 마감 승인 → 반영 승인**이다. 단계 승인은 해당 단계의 커밋까지만이며 다음 단계·최종 결과보고서·마감·원격 반영을 포함하지 않는다.

## 비목표 재확인

임계·감도 튜닝, 실제 회기 조건을 합성 회귀 검증에 새로 넣는 일, 추가 라벨링, 전사 품질 개선, 새 모델 도입, 임상가 개인 마이크 등 아키텍처 변경은 하지 않는다. 실제 회기의 임상적 유효성을 AI가 판정하지 않으며, 라벨·미디어·전사·파이프라인 산출물을 저장소나 외부 서비스로 내보내지 않는다.
