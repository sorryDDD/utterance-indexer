## 무엇을 하는가

현행 `docs/topics/` 체계가 한 색인에 논의 요약·미해결·주장 판정·결론·구현 현황을 겹쳐 두는 구조를 걷어낸다. 논의에서 나온 모든 주장을 판정 대상으로 관리하지 않고, **질문·결정·현행**을 각각 알맞은 정본에 한 번만 기록한다.

| 알고 싶은 것 | 정본 | 역할 |
|---|---|---|
| 무엇을 조사했고 왜 그런 생각이 나왔는가 | `docs/topics/` | 근거·반론·남은 질문 |
| 작업지시자가 무엇을 선택했는가 | `docs/decisions.md` | 승인된 결정 |
| 지금 실제로 무엇이 동작하는가 | 코드·매뉴얼·`AGENTS.md` | 구현된 현행 상태 |
| 언제 무엇을 실행하고 검증했는가 | Issue·계획·보고서·orders | 작업 이력과 승인 증거 |

타스크 산출물은 기존 위치와 역할을 유지한다. 새 체계는 산출물을 다시 요약하는 장부가 아니라, 서로 다른 질문에 답하는 정본의 경계를 분명히 하는 구조다.

## 왜 하는가

루트의 `thread_structure_diagnosis.md`가 실측한 핵심 문제는 주장 수가 아니라 **하나의 결정이 여러 스레드·색인·보고서·orders·`AGENTS.md`에 복제되고, 승인·구현·검증이 한 상태 칸에 섞인다는 것**이다. 실제로 하나의 승인 뒤 관련 색인의 주장 행만 갱신되지 않은 사례가 있었고, `채택 · 부분 구현`처럼 상태 접두어 뒤의 자유 서술이 실제 상태 모델을 떠맡았다.

진단서의 값싼 처방인 체크리스트·다축 상태·역참조 자동화는 누락을 줄일 수 있지만, 기존 116개 주장을 계속 관리 대상으로 남긴다. 이 타스크는 상태를 더 정교하게 만드는 대신 **승인된 선택만 결정 객체로 승격**하여 관리할 객체 수와 갱신 표면을 함께 줄인다.

## 작업 루프 판정

**일반 작업 루프**로 진행한다. 도착 구조와 변경 방향은 작업지시자가 채택했으며, 구현 중 밝혀질 것은 현재의 채택 행을 몇 개의 원자적 결정으로 합칠지와 각 색인의 남은 질문을 어떻게 축약할지다. 이 질문들은 문서를 대조하며 풀 수 있고 답에 따라 작업 방향이 바뀌지 않는다.

착수 시점에 답을 모르는 질문은 다음 세 가지다.

1. 현행 채택 행 23개가 중복을 합친 뒤 몇 개의 독립 결정으로 정리되는가.
2. 색인의 현재 상태·결론 중 결정이 아니라 실측 발견인 문장을 어느 원문 보고서나 조사 글에 연결해야 하는가.
3. 루트의 임시 진단서를 새 체계에서 어떤 기록으로 보존하는 것이 가장 자연스러운가.

## 어떻게 바꾸는가

### 1. 작업 규약의 정본을 먼저 고친다

`docs/manual/working_protocol.md`의 논의 스레드 규칙을 다음 원칙으로 교체한다.

- 논의 스레드는 **질문·근거·반론·미해결을 보존하는 탐구 기록**이다. 승인 여부나 구현 상태의 정본이 아니다.
- 스레드 안내문은 `README.md`이며 `질문 · 상태(열림/닫힘) · 관련 결정 · 남은 질문`만 둔다.
- 번호 붙은 조사 글은 기존처럼 작성일·작성자·근거를 밝히고 시간순으로 쌓는다. 기존 글 불변과 번호 불변은 유지한다.
- 글 말미의 강제 `## 주장` 절과 색인의 「오간 주장」 표·여섯 상태는 폐지한다. 제안이 있으면 본문에 명확히 쓰되, 승인되기 전까지는 결정 장부에 올리지 않는다.
- `docs/decisions.md`는 **작업지시자가 명시적으로 승인한 선택의 단일 정본**이다. 결정은 `D-NNN` 식별자를 받고 `유효 / 대체됨` 두 상태만 가진다.
- 결정 한 항목에는 독립적으로 뒤집을 수 있는 선택 하나만 둔다. 승인·범위·근거를 기록하되 구현·검증 상태는 기록하지 않는다.
- 실측 수치와 발견은 최초 정식 결과보고서나 조사 글을 기준 앵커로 삼고 다른 문서는 이를 참조한다. 결정 장부는 근거를 다시 논증하지 않는다.
- 매뉴얼·`AGENTS.md`·코드는 구현된 현행 상태만 서술한다. 승인됐지만 미구현인 결정은 Issue·계획에 남고 현행 문서에 앞서 들어가지 않는다.
- AI 에이전트가 답변에서 논의 글을 참조할 때의 기존 주장 각주 규칙은 새 구조에 맞춘다. 조사 글은 핵심 내용·근거·인용 시점을, 결정은 식별자·결정문·상태·승인 시점을 함께 밝혀 식별자만 던지지 않는다.

방법론 규칙을 고친 뒤 `AGENTS.md` §3의 작동 발췌를 같은 변경에서 맞춘다.

### 2. 결정 장부를 만든다

`docs/decisions.md`를 만들고 다음 고정 형식을 사용한다.

```markdown
## D-001-short-english-slug

- **제목**: 사람이 읽는 결정 제목
- **상태**: 유효
- **결정**: 한 문장의 원자적 선택
- **범위**: 이 결정이 적용되는 경계
- **승인**: 승인 관문과 날짜
- **근거**: 결과보고서·조사 글 링크
```

영문 슬러그는 소문자 kebab-case로 고정해 결정 제목을 고쳐도 스레드의 직접 링크가 깨지지 않게 한다.

기존 색인의 `채택` 행을 기계적으로 1:1 이관하지 않는다. 다음 순서로 대조한다.

1. `채택` 행마다 실제 작업지시자 승인 기록을 타스크 완료보고서·orders에서 확인한다.
2. 같은 선택을 반복한 행은 하나의 결정으로 합친다.
3. 스키마 존재와 표시 의무처럼 독립적으로 바뀔 수 있는 선택은 별도 결정으로 나눈다.
4. 단순 실측 발견, 완료 사실, 구현 상태는 결정 장부에서 제외하고 원문을 정본으로 남긴다.
5. 명시적 승인 증거가 없는 추천은 이관하지 않고 조사 기록으로만 보존한다.

기존 결정의 역사적 순서를 억지로 복원하지 않고, 이 타스크에서 처음 부여하는 `D-NNN`은 현재 유효한 결정의 정리 순서로 매긴다. 이후 대체된 결정은 지우지 않고 상태와 대체 결정을 기록한다.

### 3. 아홉 스레드의 안내문을 단순화한다

현존 아홉 폴더의 `000_색인.md`를 각각 `README.md`로 이름을 바꾸고 내용을 새 형식으로 다시 쓴다.

- 질문은 기존 「무엇을 논의하는가」에서 가져온다.
- 상태는 `열림 / 닫힘`만 쓴다. 결론을 승인했다는 뜻이 아니라 남은 질문이 있는지를 나타낸다.
- 승인된 결과는 결정문을 복사하지 않고 결정 표제로 바로 가는 `D-NNN` 앵커 링크로만 연결한다.
- 미해결 목록에서는 이미 완료됐거나 다른 타스크가 소유한 구현 현황을 걷고, 이 스레드의 질문에 아직 답하지 못한 것만 남긴다.
- 기존 번호 글은 이름과 내용을 변경하지 않는다. 과거 `NNN#NN#N` 인용이 가리키는 원문도 그대로 보존한다.

현재 색인의 장문 요약·주장 표·결론에서 사라지는 내용은 세 갈래로 처리한다.

- 승인된 선택은 결정 장부로 옮긴다.
- 실측·문헌 발견은 원래 번호 글이나 결과보고서를 참조한다.
- 미승인 추천은 번호 글에 남겨 두되 현재 상태 장부로 다시 옮기지 않는다.

### 4. 진단서와 안내 문서를 정리한다

- 루트의 임시 `thread_structure_diagnosis.md`는 `docs/tech/thread_structure_diagnosis.md`로 옮기고 이동 뒤 깨지는 상대 링크만 고친다. 진단 내용과 수치는 고치지 않는다.
- `docs/document_map.md`에 결정 장부, 간소화된 스레드 구조, 진단 기록의 위치를 반영한다.
- 기존 색인 경로를 직접 가리키는 현행 안내 링크는 새 `README.md` 경로로 바꾼다. 역사적 타스크 산출물의 당시 서술은 사실관계가 깨지지 않는 한 소급 개작하지 않는다.

### 5. 최종 결과를 기록한다

`docs/report/task_m010_7_report.md`에 계획 대비 변경, 결정 이관 수, 스레드별 축약 결과, 검증 결과와 남은 한계를 기록한다. 완료일의 `docs/orders/20260831.md`에는 일반 작업 완료 기록을 남긴다.
