# 문서 위치 지도

> **어떤 문서가 어디에 있는지** 안내하는 지도다 — "무엇이 존재하는가"를 빠짐없이 세는 장부가 아니다.
> 새 문서는 아래 분류에 맞는 위치에 두고, 이 지도를 갱신한다. 폴더·파일명·지도가 분류를 대신하므로 모든 파일을 등재할 필요는 없다.

---

## 프로젝트 운영

권위 구조의 정의는 작업 규약 §0에 있다. 본 지도는 위치만 안내한다.

| 문서 | 위치 | 내용 |
|---|---|---|
| 작업 규약 | `docs/manual/working_protocol.md` | **작업 방법론의 단일 정본** — 권위 구조·역할 분담·승인 목록·문서 규칙·Git 규칙·세 작업 루프 |
| 프로젝트 지침 | `AGENTS.md` | 매 세션 로드되는 작동 발췌본 + **프로젝트 고유·동적 정보의 정본**(§1) |
| 도구 어댑터 | `CLAUDE.md` | `@AGENTS.md` 한 줄. 규칙을 담지 않는다 |
| 거시 로드맵 | `docs/manual/roadmap.md` | 마일스톤 목록과 운용 제약의 정본. 현재 단계는 `AGENTS.md` §1 |
| 문서 위치 지도 | `docs/document_map.md` | 본 문서 (문서가 어디 있는가) |

주제별 발췌본(「브랜치 전략」·「문서 체계」 등)은 두지 않는다 — 정본의 해당 절을 읽는다(규약 §0 ④).

## 타스크 산출물

계획서는 `docs/plans/`, 단계별 완료보고서는 `docs/working/`, 최종 결과보고서는 `docs/report/`, 오늘 할 일은 `docs/orders/`에 둔다. 파일명 규칙은 작업 규약 §4를 따르며, **개별 타스크 산출물은 본 지도에 등재하지 않는다** — 파일명이 곧 색인이다.

**새 설계 결정은 그 결정을 낳은 타스크의 산출물에 남긴다.** 별도 결정 로그 폴더를 두지 않는다.

## 설계·도메인 자산 〔기입〕

| 문서 | 위치 | 상태 |
|---|---|---|
| 〔기입〕 | `docs/design/…` | |
| 〔기입〕 | `docs/domain/…` | |

## 여기 없는 것

**방법론 학습 교재**는 별도 저장소에 있다 — 교재는 학습자를 따라다니는 자산이므로 프로젝트에 속하지 않는다. 병행하는 경우 그 경로는 `AGENTS.md` §6에 있다.

**방법론 규칙의 정본이 유지되는 곳**은 프로젝트 생성 템플릿이다. 여기 있는 정본은 그 복제본이며, 개선하면 템플릿에 반영한다(규약 §6).
